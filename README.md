# 🌪️ 나의 터빈일지

AI 기반 풍력 터빈 블레이드 손상 탐지 및 예방 정비 대시보드

드론으로 촬영한 풍력 터빈 이미지·동영상을 YOLO 모델로 분석해 `Damage`(손상)와
`Dirt`(오염)를 탐지하고, 탐지 신뢰도와 영역 크기를 바탕으로 위험 등급과 관리자
권장 조치를 제공하는 해커톤용 예방정비 데모입니다. 분석 결과는 서버에 저장되어
**현장 관리자들이 실시간으로 공유**하고, 위험 등급은 담당자에게 **자동으로 푸시
알림**이 발송됩니다.

## 주요 기능

- JPG/PNG 터빈 이미지 **및 MP4/MOV/AVI/MKV 동영상** 업로드
- YOLO 기반 손상 및 오염 탐지
- 신뢰도 70% 이상 탐지 결과의 Bounding Box 표시
- **동영상은 프레임을 샘플링해 위험도가 가장 높은 순간을 자동으로 찾아내고,
  탐지 박스가 그려진 타임랩스 영상으로 결과를 재생**
- 탐지 영역의 이미지 대비 면적 계산
- 정상·관찰·주의·위험 등급 자동 산정
- 등급별 권장 조치와 알림 정책 표시
- 관리자 Overview 요약 카드와 오늘의 우선 점검 대상 배너
- AI 점검 브리핑(점검 요약 + 우선 권장 작업 4가지) 자동 생성
- 이전 점검 대비 위험도 및 손상 변화 비교
- 객체별 위험도 계산 근거(클래스 가중치·면적비·신뢰도) 상세 제공
- 현장 제출용 PDF 점검보고서 다운로드
- **ntfy 푸시 알림으로 담당자에게 실시간 발송** — 버튼 클릭 시 발송되며,
  `위험` 등급은 버튼을 누르지 않아도 자동 발송됩니다 (발송 성공/실패 화면 표시)
- **여러 관리자가 함께 보는 공유 점검 이력** — 한 명이 분석한 결과를 다른
  관리자도 이력 목록에서 확인하고, 선택해서 그 당시 화면 그대로 다시 볼 수 있음
- 라이트 테마의 카드형 산업용 대시보드 UI

> 현재 버전은 해커톤 데모입니다. 점검 이력은 서버의 JSON 파일에 저장되어
> 모든 관리자가 함께 보지만, 로컬 파일 기반이라 서버를 재배포/재시작하면
> 함께 초기화됩니다 (진짜 영구 저장은 외부 데이터베이스가 필요합니다).
> 첫 점검의 `이전 점검 대비` 카드는 발표용 예시 기준값을 사용하며 화면에
> `DEMO BASELINE`으로 표시됩니다. 같은 터빈의 다음 점검부터는 실제 직전 결과와 비교합니다.

## 빠른 시작

### 1. 저장소와 모델 확인

프로젝트 루트에 학습된 모델 `best.pt`가 있어야 합니다.

```text
wind-demo/
├── .streamlit/
│   └── config.toml       # Streamlit 라이트 테마
├── samples/
│   ├── damage.png        # 손상 데모 이미지
│   ├── dirt.png          # 오염 데모 이미지
│   └── normal.png        # 정상 데모 이미지
├── app.py                # Streamlit 대시보드
├── config.py             # 모델 경로 설정
├── severity.py           # 위험도 계산 및 등급 판정 (이미지·동영상 공용)
├── history_store.py      # 공유 점검 이력 저장/조회 (JSON 파일)
├── best.pt               # 학습된 YOLO 모델
├── requirements.txt
├── packages.txt          # Streamlit Cloud용 apt 패키지 (ffmpeg)
├── history_store.json    # 런타임에 자동 생성되는 공유 이력 (git 추적 제외)
└── README.md
```

모델이 저장소에 포함되지 않았다면 팀 공유 드라이브에서 받은 `best.pt`를
프로젝트 루트에 복사하세요. GitHub의 일반 파일 제한을 넘는 모델은 Git LFS나
별도 공유 링크로 관리하는 것을 권장합니다.

### 2. 가상환경 생성

Python 3.10 또는 3.11 사용을 권장합니다.

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. 의존성 설치

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

동영상 탐지 결과 재생 기능은 시스템 `ffmpeg`가 필요합니다 (Python 패키지가
아닙니다). 로컬에 없다면 설치하세요.

macOS: `brew install ffmpeg`
Ubuntu/Debian: `sudo apt-get install ffmpeg`
Windows: [ffmpeg.org](https://ffmpeg.org/download.html)에서 받아 PATH에 추가

ffmpeg가 없어도 앱 자체는 정상 동작하며, 동영상 업로드 시 타임랩스 대신
위험도가 가장 높은 대표 프레임만 정지 이미지로 보여줍니다.

### 4. 실행

프로젝트 루트에서 다음 명령을 실행합니다.

```bash
streamlit run app.py
```

브라우저가 자동으로 열리지 않으면 터미널에 표시된 주소(기본값
`http://localhost:8501`)로 접속하세요.

## 사용 방법

1. `점검 입력`에서 `samples/`의 이미지, 드론 촬영 이미지, 또는 동영상을 업로드합니다.
2. 점검 대상의 터빈 ID를 목록(터빈-01 ~ 터빈-10)에서 선택합니다.
3. 모델 추론이 끝날 때까지 잠시 기다립니다.
4. 탐지 이미지(또는 탐지 결과 타임랩스 영상), 위험도 등급, 권장 조치와 알림 정책을 확인합니다.
5. 필요하면 `🔔 담당자 알림` 버튼으로 현재 결과를 ntfy 푸시 알림으로 발송합니다 (`위험` 등급은 자동 발송됨).
6. 하단의 탐지 상세, 상세보기(등급 기준·계산 근거·통계), 점검 이력에서 결과를 비교합니다.
7. 점검 이력에서 과거 기록(다른 관리자가 분석한 것 포함)을 선택해 그 당시 화면을 다시 볼 수 있습니다.

발표 시에는 `normal.png` → `dirt.png` → `damage.png` 순으로 시연하면 등급과
조치가 달라지는 흐름을 설명하기 좋습니다.

## 동영상 업로드 및 탐지 결과 재생

이미지뿐 아니라 `mp4`/`mov`/`avi`/`mkv` 동영상도 업로드할 수 있습니다.

- 1초 간격으로 최대 30프레임을 샘플링해 각각 탐지하고, **위험도가 가장 높은
  프레임**을 대표 결과로 등급·위험도·PDF·알림에 사용합니다
  ([app.py](app.py)의 `VIDEO_SAMPLE_INTERVAL_SEC`/`VIDEO_MAX_FRAMES`에서 조정 가능)
- 탐지 결과는 샘플링한 프레임들에 박스를 그려 이어붙인 **타임랩스 영상**(2fps
  재생)으로 보여줍니다 — 원본 동영상 전체를 프레임 단위로 재인코딩하는 것이
  아니라, 분석에 사용한 프레임만 모은 짧은 영상입니다
- 타임랩스 인코딩은 시스템 `ffmpeg`(H.264)로 처리합니다. `opencv-python-headless`는
  라이선스 문제로 H.264 인코딩을 지원하지 않아 브라우저에서 재생이 안 되기
  때문입니다. ffmpeg가 없거나 인코딩에 실패하면 에러 없이 대표 프레임 정지
  이미지로 자동 대체됩니다

## 담당자 알림 (ntfy 푸시)

우측 패널의 `🔔 담당자 알림` 버튼을 누르면 현재 분석 결과를
[ntfy](https://ntfy.sh) 푸시 알림으로 실제 발송합니다. `위험` 등급으로
판정되면 버튼을 누르지 않아도 **자동으로 한 번** 발송됩니다 (같은
업로드·터빈ID 조합에서는 다른 버튼 클릭 등으로 화면이 재실행돼도 중복
발송되지 않습니다).

- 기본 topic: `turbine-alarm-1234` ([app.py](app.py)의 `NTFY_TOPIC` 상수에서 변경 가능)
- 메시지 본문: 등급(`🟢 정상 (Lv0)` ~ `🔴 위험 (Lv3)`), 터빈 ID, 위험도, Damage/Dirt
  건수, 재확인 건수, 권장조치, 발송 시각
- 우선순위: `주의`·`위험` 등급은 priority 4, `정상`·`관찰`은 priority 3으로 발송
- 버튼 아래에 발송 상태가 표시됩니다.
  - 발송 전: `외부 채널 연동 전`
  - 성공: `ntfy 담당자 알림 발송 완료` (자동 발송이면 `(위험 등급 자동 발송)` 표시)
  - 실패: `알림 발송 실패: ...` (네트워크 오류 등 원인 포함)

실시간으로 폰에서 받아보려면 [ntfy 앱](https://ntfy.sh)을 설치하고 위 topic을
구독하세요. `turbine-alarm-1234`는 인증 없는 공개 topic이므로 데모/테스트
용도로만 사용하고, 실서비스에서는 비공개 topic이나 자체 호스팅 ntfy 서버 사용을
권장합니다.

## 공유 점검 이력

점검 이력은 브라우저 세션이 아니라 **서버의 `history_store.json` 파일**에
저장됩니다. 같은 배포에 접속한 모든 관리자가 서로의 점검 결과를 실시간으로
보고, 선택해서 그 당시 화면(탐지 이미지, 등급, AI 브리핑, 이전 대비 비교까지)을
그대로 다시 볼 수 있습니다.

- 이력 표에서 행을 선택하면 `🔍 불러오기`, `🗑️ 테스트 기록 삭제` 버튼이 나타납니다.
  불러오기를 누르면 그 화면이 그대로 열립니다 (파란 배너로 "불러온 점검 기록"임을
  표시). `✕ 불러오기 닫기`로 닫을 수 있습니다
- 새 이미지/영상을 업로드하면 불러오기 화면은 자동으로 닫힙니다. 반대로
  이미 업로드된 파일이 있으면 불러오기보다 업로드 결과가 우선 표시되니,
  이력을 보려면 업로드 목록에서 파일을 먼저 제거하세요
- 동영상으로 분석한 기록은 이력에 **대표 프레임 이미지만** 저장됩니다
  (타임랩스 영상 자체는 용량 문제로 저장하지 않음)
- 최근 200건까지 보관하며 오래된 기록부터 자동으로 정리됩니다
  ([history_store.py](history_store.py)의 `MAX_HISTORY`에서 조정 가능)
- 파일 기반 저장이라 **서버를 재배포/재시작하면 이력도 함께 초기화**됩니다.
  같은 배포가 떠 있는 동안에는 유지됩니다

### 테스트 기록 삭제 (하드 삭제 — 데모 전용)

`🗑️ 테스트 기록 삭제` 버튼은 확인 팝업을 거쳐 선택한 기록을 파일에서
**영구적으로 제거**합니다 ([history_store.py](history_store.py)의
`delete_entries()`). 이 목록은 모든 관리자가 함께 보므로 삭제는 모두의
화면에 즉시 반영되고 되돌릴 수 없습니다.

이 기능은 데모/테스트 중 잘못 올린 기록을 정리하기 위한 편의 기능입니다.
**실서비스에서는 하드 삭제 대신 아카이브(archive) 또는 무효(invalidate)
처리 방식을 권장합니다** — 점검 이력은 안전·정비 감사(audit trail) 성격이
강해서, 실수로 삭제되거나 나중에 "누가 왜 지웠는지" 추적이 안 되는 것이
더 큰 문제가 될 수 있습니다. 예를 들어 레코드에 `status: "active" |
"archived" | "invalid"` 필드를 추가해 목록에서는 숨기되 데이터는 보존하고,
삭제 사유와 처리자를 함께 기록하는 방식이 적합합니다.

## 위험도 판정 방식

- 신뢰도 40% 미만: 오탐 가능성이 높아 판정에서 제외
- 신뢰도 40% 이상 70% 미만: 자동 점수에서 제외하고 재확인 대상으로 표시
- 신뢰도 70% 이상: 클래스 가중치, 탐지 면적, 신뢰도로 위험도 계산
- `Damage`는 `Dirt`보다 높은 위험 가중치를 사용

| 위험도 | 등급 | 기본 권장 조치 |
|---:|---|---|
| 0 | 정상 | 이상 없음 |
| 0 초과 ~ 15 미만 | 관찰 | 정기점검 시 확인 |
| 15 이상 ~ 40 미만 | 주의 | 점검 계획 수립 |
| 40 이상 | 위험 | 즉시 점검 필요 |

판정 임계치와 알림 정책은 [severity.py](severity.py)에서 조정할 수 있습니다.

## 모델 경로 변경

기본 모델 경로는 프로젝트 루트의 `best.pt`입니다. 다른 모델을 사용할 때는
`WIND_MODEL_PATH` 환경변수로 경로를 지정할 수 있습니다.

macOS/Linux:

```bash
WIND_MODEL_PATH=/absolute/path/to/model.pt streamlit run app.py
```

Windows PowerShell:

```powershell
$env:WIND_MODEL_PATH="C:\path\to\model.pt"
streamlit run app.py
```

## 문제 해결

### 모델 파일을 찾을 수 없습니다

`best.pt`가 프로젝트 루트에 있는지 확인하거나 `WIND_MODEL_PATH`에 올바른
절대경로를 지정하세요.

### `streamlit` 명령을 찾을 수 없습니다

가상환경이 활성화되어 있는지 확인한 뒤 `pip install -r requirements.txt`를
다시 실행하세요. 명령 대신 `python -m streamlit run app.py`를 사용할 수도 있습니다.

### 첫 분석이 느립니다

첫 실행 시 모델 로딩 때문에 시간이 더 걸릴 수 있습니다. 이후 분석에서는
Streamlit의 모델 캐시를 재사용합니다. 현재 데모는 CPU에서도 실행되지만 GPU가
있으면 추론 시간이 단축됩니다.

### `알림 발송 실패`가 표시됩니다

`https://ntfy.sh`로 나가는 아웃바운드 연결이 방화벽/프록시에 막혀 있지 않은지
확인하세요. 사내망이나 오프라인 환경에서는 ntfy.sh에 접속할 수 없어 항상
실패로 표시됩니다. 화면에 표시되는 오류 메시지에 실제 원인(타임아웃, DNS 실패
등)이 함께 나옵니다.

### 동영상 업로드 후 타임랩스 대신 정지 이미지만 나옵니다

시스템에 `ffmpeg`가 없거나 H.264 인코딩에 실패한 경우입니다. 캡션에 "타임랩스
영상 생성 실패로 대표 프레임만 표시"라고 안내되며, 로컬은 `ffmpeg`를 설치하고
Streamlit Cloud는 `packages.txt`에 `ffmpeg`가 포함되어 있는지, 배포 후
Reboot을 했는지 확인하세요.

### 다른 관리자가 올린 점검이 이력에 안 보입니다

`history_store.json`이 있는 서버 프로세스가 맞는지 확인하세요 (로컬에서 포트를
여러 개 띄워 테스트 중이라면 각 프로세스가 같은 작업 디렉터리를 보고 있어야
합니다). Streamlit Cloud처럼 하나의 배포에 접속했다면 자동으로 공유됩니다.
재배포/재시작 직후라면 이력이 초기화된 것이 정상입니다.

## 향후 개선

- 드론 촬영 결과 자동 업로드
- GPS 기반 터빈 위치 연동
- Slack/SMS/이메일 등 추가 알림 채널 (현재는 ntfy 푸시만 실제 발송)
- 비공개 topic 또는 자체 호스팅 ntfy 서버 연동
- 점검 일정 및 작업자 배정
- 외부 데이터베이스 기반 점검 이력 영구 저장 (현재는 서버 로컬 JSON 파일 —
  재배포 시 초기화됨)
- 관리자별 로그인/계정 구분 (현재는 누가 분석했는지 구분 없이 전체 공유)
- 원본 동영상 전체 길이의 탐지 결과 영상 (현재는 샘플링한 프레임만 재생)
